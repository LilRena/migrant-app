# ТЗ: KFU Migrant — MVP

Веб-приложение для иностранных студентов КФУ и сотрудников миграционного центра.

## Объём MVP

**Рабочий раздел (настоящий бэкенд + база + фронтенд): «Документы».**
Полный цикл: студент входит → видит свой пошаговый алгоритм документов со сроками → загружает документ → сотрудник проверяет → статус и прогресс обновляются у студента.
Чтобы цикл работал, в него входят: вход и регистрация, минимальные данные студента (страна, дата въезда, сроки визы и регистрации) и простая панель проверки для сотрудника.

**Макеты на демо-данных (только фронтенд, без бэкенда): Главная, Профиль.**
Сделаны качественно, как настоящие экраны, но берут данные из демо-файла. Позже переключаются на настоящий API без переделки вёрстки (см. «Демо-режим»).

**Не входит:** онлайн-очередь, чат с куратором, новости на бэкенде, push-уведомления, несколько языков, мобильное приложение.

## Сроки — только демо

Реальных шагов и сроков от миграционного центра пока нет. Поэтому:
- Шаги и правила сроков хранятся в одном файле `data/steps_demo.json`, а не в коде.
- Срок задаётся правилом, а не датой: «N дней после въезда», «за N дней до окончания визы» или «без срока». Дата у каждого студента считается автоматически.
- Скрипт `scripts/load_steps.py` загружает файл в базу. Чтобы вставить реальные данные, достаточно заменить файл и перезапустить скрипт — код не трогаем.
- В интерфейсе, пока данные демо, показывается пометка «Демо-данные».

## Правила работы (для Claude Code)

1. Работай строго по этапам. После каждого этапа остановись, запусти тесты и жди подтверждения.
2. В конце этапа отчитайся по каждому пункту этапа отдельно: сделано / не сделано / сделано иначе и почему. Без общих слов.
3. Не добавляй функции, которых нет в ТЗ. Если что-то неясно — спроси.
4. Никаких секретов в коде: всё через `.env`, в репозитории только `.env.example` (с заглушками вроде `change-me`). Значений по умолчанию для `SECRET_KEY` и `DATABASE_URL` в коде быть не должно: если переменная не задана, приложение не запускается и выдаёт понятную ошибку. Репозиторий публичный, поэтому любой ключ или пароль из кода известен всем. `.gitignore` обязан содержать `.env` и `uploads/`.
5. Каждый эндпоинт с данными студента проверяет владельца. На это обязательны тесты.
6. Тексты интерфейса на русском. Код, имена и комментарии — на английском, комментарии короткие и понятные новичку.

## Стек

- Бэкенд: Python 3.12, FastAPI, SQLAlchemy 2, Alembic, Pydantic v2, pydantic-settings
- База: PostgreSQL
- Авторизация: JWT (python-jose), пароли — bcrypt (passlib), срок токена 30 минут
- Тесты: pytest + httpx (TestClient), отдельная тестовая база
- Фронтенд: HTML + CSS + чистый JavaScript (ES-модули, без сборщика)

## Модель данных

Все даты — `Date`/`DateTime`, не строки. Старая таблица `tasks` удаляется: её роль выполняют шаги.

**users** — id, email (уникальный), hashed_password, full_name, role (`student` | `staff`), created_at

**student_profiles** (1 к 1 с users) — user_id, country_code, faculty, course, arrival_date, visa_expiry, registration_expiry

**step_templates** — шаблон алгоритма
- id, country_code (NULL = для всех стран), order
- title, description, location (кабинет, адрес)
- deadline_type: `days_after_arrival` | `days_before_visa_expiry` | `none`
- deadline_days
- requires_upload (bool)
- is_demo (bool)

**student_steps** — прогресс студента
- id, student_id, template_id; уникальная пара (student_id, template_id)
- status: `todo` | `submitted` | `approved` | `rejected`
- due_date
- file_path, uploaded_at
- staff_comment, reviewed_by, reviewed_at

## API (только раздел «Документы»)

**Авторизация**
- `POST /auth/register` — только роль `student`
- `POST /auth/login` → `{access_token, token_type}`; ошибки — 401
- `GET /auth/me`

**Данные студента**
- `GET /me/profile`, `PUT /me/profile` — когда заполнены страна и дата въезда, студенту назначаются шаги и считаются сроки; при изменении дат сроки пересчитываются

**Шаги и документы**
- `GET /me/steps` — шаги по порядку + прогресс (`done`, `total`) + флаг `is_demo`
- `POST /me/steps/{id}/upload` — только PDF/JPG/PNG, до 10 МБ, случайное имя файла; статус → `submitted`
- `GET /me/steps/{id}/file`

**Сотрудник** (только `staff`)
- `GET /staff/students` — фильтр: есть документы на проверке / есть просроченные шаги
- `GET /staff/students/{id}/steps`
- `GET /staff/steps/{id}/file`
- `POST /staff/steps/{id}/review` — `{decision: approve|reject, comment}`; при отказе комментарий обязателен

## Демо-режим фронтенда

- Все данные фронтенд получает только через `js/api.js`.
- Для разделов без бэкенда `api.js` отдаёт данные из `js/demo-data.js` **в том же формате**, в каком их потом будет отдавать настоящий API (например, `getDashboard()` возвращает объект, как будущий `GET /me/dashboard`).
- Чтобы подключить настоящий бэкенд к макету, меняется одна функция в `api.js`, вёрстка не трогается.
- Формат демо-данных описать в комментарии в начале `demo-data.js`.

## Экраны

Нижнее меню студента: Главная · Документы · Профиль. Дизайн — по прототипу `kfu_migrant_prototype.html`: синяя гамма КФУ, мобильная вёрстка в первую очередь, одинаковый каркас на всех экранах.

**Рабочие**
- **Вход/регистрация** — email, пароль, имя; при 401 — возврат на вход.
- **Документы** — прогресс «X из Y»; шаги по порядку: название, срок (с пометкой «осталось N дней» / «просрочено»), где получить, статус, комментарий при отказе; загрузка файла; фильтр по статусу; пометка «Демо-данные».
- **Панель сотрудника** — список студентов с фильтром, карточка студента со шагами, просмотр файла, «Принять» / «Отклонить с комментарием».

**Макеты на демо-данных**
- **Главная** — только карточки-выжимки, каждая ведёт на свой экран: приветствие, баннер ближайшего дедлайна, следующие 2 шага, ближайший визит, 2 новости.
- **Профиль** — личные данные, сроки визы и регистрации, куратор с кнопкой связи, язык и уведомления, выход. Без дублей из «Документов».

## Этапы

**Этап 0. Перестройка проекта**
- Перенести текущий код в новую структуру, настройки через `config.py` и `.env`, `.env.example`
- Убрать из кода fallback-значения `SECRET_KEY` и пароль базы `password123`; приложение падает при старте, если переменные не заданы
- Проверить, что `.gitignore` содержит `.env` и `uploads/`
- Alembic, первая миграция; удалить `tasks`
- pytest и тестовая база

**Этап 1. Авторизация и роли**
- Регистрация, вход, `/auth/me`, `require_staff`, `scripts/create_staff.py`
- Тесты: неверный пароль → 401, студент на `/staff/...` → 403, просроченный токен → 401

**Этап 2. Алгоритм и сроки**
- `data/steps_demo.json` (демо-шаги для всех стран, `country_code = null`, `is_demo = true`) и `scripts/load_steps.py`
- Профиль, назначение шагов, расчёт и пересчёт сроков, `GET /me/steps`
- Тесты: шаги назначаются по стране, сроки считаются верно для каждого типа правила, студент видит только свои шаги

**Этап 3. Загрузка и проверка**
- Загрузка файлов с проверками, эндпоинты сотрудника, принятие и отказ
- Тесты: нельзя загрузить файл в чужой шаг, нельзя скачать чужой файл, отказ без комментария → 422

**Этап 4. Фронтенд рабочих экранов**
- Каркас, нижнее меню, `api.js`, вход, Документы, панель сотрудника, `seed_demo.py`
- Пройти весь цикл вручную в браузере, шаги проверки описать в README

**Этап 5. Макеты**
- `demo-data.js`, Главная и Профиль на демо-данных через `api.js`
